BK FOOT — حزمة تطوير 1.3
الموسم: 2026–2027 | واجهة عربية RTL | أحمر/أبيض مع سمات فاتحة اختيارية

الموجود في هذه الحزمة
- index.html: واجهة تفاعلية لإدارة المباريات والنتائج والترتيب والإحصائيات والفرق والملاعب والأرشيف.
- قائمة 16 فريقًا أُدخلت من الصورة التي قدمها المستخدم؛ يجب التحقق من تهجئة الأسماء واعتمادها من الرابطة قبل النشر الرسمي. لم تُدخل نتائج أو نقاط من الصورة كبيانات مباريات.
- حفظ محلي في المتصفح، ونسخ احتياطي JSON مع تاريخ التصدير، واستعادة مع فحص بنية البيانات وتأكيد قبل الاستبدال، وتصدير CSV، وطباعة/حفظ PDF عبر نافذة الطباعة.
- أرشيف المواسم مستقل عن إعدادات هوية المنصة والتصاميم؛ يمكن تنزيل الأرشيف أو استيراد ملف أرشيف دون استبدال بيانات الموسم الجاري.
- الإصدار 1.3 يتحقق من صحة أعداد الأهداف ورقم الجولة، وينبه عند تكرار مواجهة الفريقين في الجولة نفسها، ويعرض تأكيدًا قبل إعادة ضبط بيانات البطولة.
- manifest.webmanifest وsw.js وأيقونات PWA لأساس التثبيت والعمل دون اتصال بعد فتح التطبيق مرة على استضافة HTTPS.
- capacitor.config.json وpackage.json كنقطة بداية لتغليف الواجهة في Android عبر Capacitor.

التشغيل المحلي
1) افتح index.html في Chrome/Edge. الحفظ المحلي يعمل، لكن Service Worker لا يعمل عند فتح الملف مباشرة من file://.
2) لتجربة PWA، شغّل خادم ملفات محليًا من هذا المجلد (مثل: python -m http.server 8080) وافتح http://localhost:8080. للنشر العام يلزم HTTPS.

بناء APK
- تم ضبط Capacitor على مجلد www/ منفصل؛ لا يستخدم جذر المشروع كأصول ويب.
- محليًا في بيئة فيها Android SDK وJDK 21: npm install ثم npm run android:add ثم npm run android:build.
- أضفت سير عمل GitHub Actions في .github/workflows/android-apk.yml. بعد رفع المشروع إلى مستودع GitHub، افتح Actions وشغّل Build BK FOOT Android APK؛ ستظهر app-debug.apk كـ Artifact إذا نجح البناء.
- بيئة العمل الحالية لا تحتوي Android SDK/Gradle، ولا تستطيع الوصول إلى الإنترنت لتنزيلهما؛ لذلك لا يوجد APK مبني في هذا الملف، ولا ندّعي أنه بُني.
- نسخة debug للتجربة فقط؛ يلزم توقيع release بمفتاح خاص قبل التوزيع العام. لا تشارك مفتاح التوقيع.

حدود مهمة — لا تدّعِ هذه الحزمة ما لم يتم تنفيذه
- هذه الحزمة ليست APK مبنيًا أو مختبرًا. لم يتم إنشاء APK في بيئة العمل هذه لعدم توفر Android SDK/Gradle.
- لا يوجد خادم مركزي أو تسجيل دخول أو صلاحيات مسؤول حقيقية أو مزامنة بين المستخدمين أو إشعارات دفع.
- حفظ البيانات محلي على الجهاز/المتصفح فقط؛ حذف بيانات المتصفح قد يفقدها. خذ نسخة JSON احتياطية.
- قائمة الفرق مأخوذة من الصورة المرفقة من المستخدم، وليست تحققًا مستقلاً من مصدر رسمي للموسم. الملاعب لا تضاف إلا بعد التحقق من العنوان/الإحداثيات.
- أضيف سجل محلي لقرارات خصم النقاط: الفريق، عدد النقاط، مرجع القرار والسبب. يظهر الخصم في النقاط المحسوبة. يجب إدخال القرارات المعتمدة فقط.
- ترتيب الجدول يحسب من النتائج المدخلة ويطبق خصم النقاط المسجل. قواعد كسر التعادل الكاملة والغرامات/العقوبات الأخرى تحتاج اعتماد اللوائح قبل الاستخدام الرسمي.
- بيانات البطولة يمكن تحديثها مركزيًا مستقبلًا بعد إضافة Backend وقاعدة بيانات ومصادقة. تحديث ملف APK نفسه يحتاج قناة توزيع موثوقة أو Google Play.

تحديث التطوير 1.2 — مراجعة سلامة محلية وهوية BK FOOT
- توحيد اسم التطبيق في إعدادات الواجهة وبيانات PWA وCapacitor.
- جعل حفظ البيانات المحلي يتعامل مع أخطاء التخزين ويعرض تنبيهًا بدل فشل صامت.
- تقييد حجم الشعارات وأنواعها لتقليل احتمال امتلاء localStorage.
- تهريب عناوين صور الشعارات قبل إدراجها في HTML لتقليل مخاطر إدخال HTML غير موثوق عبر ملف استعادة.
- تحديث سياسة Service Worker ليجلب صفحة HTML من الشبكة أولًا ويستخدم النسخة المخزنة عند انقطاع الاتصال، مع تغيير معرّف التخزين المؤقت.
- اجتاز JavaScript فحص الصياغة بواسطة Node.js. هذا ليس بديلًا عن اختبار شامل على المتصفحات والهواتف.


تحديث التطوير 1.3 — إصلاحات مراجعة
- إصلاح ترجمة عناصر التنقل عبر data-tab بدل الفهرسة، لتفادي انتقال أسماء الأقسام بعد إضافة استوديو التصاميم.
- فصل نجاح حفظ localStorage عن تحديث الواجهة حتى لا يُبلّغ عن فشل الحفظ بعد نجاحه فعليًا.
